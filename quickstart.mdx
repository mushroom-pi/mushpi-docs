This guide walks you through one working end-to-end setup: flash the firmware onto a Pico 2W, start the hub on a single-board computer, open the dashboard in your browser, and register your first grow unit. Each step is the shortest path that works; the Build & Self-Host pages carry the depth behind it.

## Before you start

You need:

- A Raspberry Pi Pico 2W.
- A hub: any single-board computer (or small PC) that can run Docker on 64-bit Linux. The maintainer tests on a Raspberry Pi 3B+ (1 GB), so that is a known-good starting point, not a requirement. The 64-bit OS is a hard requirement — the published image is built for `arm64` and `amd64`, so a 32-bit OS cannot pull it.
- Docker Engine with the Compose v2 plugin — the `docker compose` subcommand (with a space).
- A DHT11 sensor and a relay module, wired to the Pico. See [Wiring](/hardware/wiring).

## 1. Flash the Pico

1. Flash MicroPython v1.26.0 onto the Pico: hold **BOOTSEL**, connect it over USB, and drag the `.uf2` file onto the `RPI-RP2` drive. [Download v1.26.0](https://micropython.org/resources/firmware/RPI_PICO2_W-20250809-v1.26.0.uf2).
2. Get the firmware files from the [mushpi-grow repository](https://github.com/mushroom-pi/mushpi-grow).
3. Edit `config.json` and set:
   - `wifi.ssid` and `wifi.password` — your network.
   - `hub_url` — `http://<hub-ip>:3000/v1/pico-units/announce`.
   - `hub_secret` — must match the hub's `PICO_ANNOUNCE_SECRET` (step 2).
   - `device_name` — a unique name for this unit; it becomes the unit's `handle` on the hub.
4. Upload `main.py`, `config.json`, and the `app/` folder to the Pico, plus the two third-party libraries `lib/microdot.py` and `lib/urequests.py`. The repo's own tooling is the MicroPico VSCode extension, which uploads every `.py`, `.html`, and `config.json`; Thonny's file manager also works. The libraries are not tracked in the repo, so install them with `mip` or download them per the grow README.

The full flashing walkthrough — wiring, pin map, and library setup — is on the [Pico firmware page](/hardware/pico-firmware). If you would rather not edit `config.json` at all, the Pico has an access-point provisioning mode: with no Wi-Fi configured it boots a form at `192.168.4.1` where you enter your network credentials. That flow is also covered on the Pico firmware page.

## 2. Start the hub

On the hub machine:

```bash
git clone https://github.com/mushroom-pi/mushpi-ops.git mushpi-ops
cd mushpi-ops
cp .env.example .env
```

Edit `.env` and set `PICO_ANNOUNCE_SECRET` to a value you choose. Pico units send it on every announce, and it must match `hub_secret` in their `config.json`.

```bash
docker compose up -d
```

This pulls the published image `ghcr.io/mushroom-pi/mushpi` and starts one container that serves the backend and the dashboard together on port 3000 — you never build anything locally. To run a specific release, set `MUSHPI_IMAGE_TAG` in `.env` (it defaults to `latest`).

The full deployment walkthrough — SD-card provisioning, first boot, and the environment options — is on the [Self-hosting page](/deployment/self-hosting).

## 3. Open the dashboard

Open a browser on any device on the same network and go to `http://<hub-ip>:3000`. Find the hub's address with `hostname -I` on the hub. The dashboard loads with an empty unit list — that is expected.

## 4. Register your Pico unit

Power on the Pico. It connects to your Wi-Fi and announces itself to the `hub_url` you set in `config.json`. The hub registers it by its `handle` — the `device_name` from `config.json` — and it appears in the dashboard within a minute or two.

If it does not appear, check that `hub_secret` and `PICO_ANNOUNCE_SECRET` match, and that `hub_url` points at the hub's real address. The [Pico registration page](/deployment/pico-registration) covers the flow and its troubleshooting in detail.

## 5. Start monitoring

Click your unit to open its detail view: live readings update every 60 seconds, alongside relay states and the temperature and humidity charts. To track a grow run, open **Batches**, create a batch, and set your target temperature and humidity ranges. Mushroom Pi holds those conditions from then on.

**No hardware handy?** The [mushpi-mock service](https://github.com/mushroom-pi/mushpi-mock) mirrors the Pico's REST API exactly, so the hub cannot tell it apart from a real unit — ideal for testing recipes or developing. See [Mock Pico](/development/mock-pico).
