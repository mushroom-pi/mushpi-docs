By default, the Mushroom Pi dashboard is reachable only from devices on the same local network as the hub. The recommended way to reach it from anywhere else is **Tailscale** — a private mesh VPN built on WireGuard. Your devices connect directly to each other over an encrypted tunnel: no port forwarding, nothing exposed to the public internet, and the dashboard stays reachable only from devices on your tailnet. MagicDNS gives the hub a stable hostname you can reach from any of them.

## The plain path: Tailscale on the hub

1. **Install Tailscale on the hub.** Run the official install script on the Pi that hosts the Mushroom Pi container:

   ```bash
   curl -fsSL https://tailscale.com/install.sh | sh
   ```

2. **Authenticate the hub to your tailnet.** Start Tailscale and follow the authentication link it prints:

   ```bash
   sudo tailscale up
   ```

   Open the URL in a browser, sign in, and authorize the device. The hub is now a member of your tailnet.

3. **Reach the dashboard by hostname.** Install Tailscale on your phone, laptop, or any other device and sign in to the same tailnet. Then open:

   ```
   http://<magicdns-hostname>:3000
   ```

   The hostname is the MagicDNS name Tailscale assigns to the hub — something like `raspberrypi.tail1234.ts.net`. The dashboard loads exactly as it does on your LAN.

<Note>
MagicDNS assigns a stable hostname to every device on the tailnet. It is enabled in the Tailscale admin console (on by default for new accounts), and each device's name is listed there.
</Note>

## HTTPS with `tailscale serve`

The plain path serves the dashboard over plain HTTP. The recommended way to get HTTPS is **`tailscale serve`**: it terminates TLS for the hub's tailnet hostname and proxies requests to the dashboard's port 3000, so the same MagicDNS name is reached over `https://`.

When TLS is terminated upstream like this, tell the server about it: set `APP_HTTPS_ENABLED=true` in `.env` and recreate the stack with `docker compose up -d`. The flag does not configure TLS itself — it declares that the browser-facing deployment is genuinely served over HTTPS, which makes the server send the HSTS header and the CSP `upgrade-insecure-requests` directive.

**It must stay `false` otherwise.** On a plain-HTTP deployment those directives make the browser rewrite the dashboard's own asset URLs to `https://`, which renders a blank page.

## Headscale — the self-hosted escape hatch

Tailscale's coordination service is hosted by Tailscale. For anyone who would rather not use that hosted service, [Headscale](https://github.com/juanfont/headscale) is an open-source, self-hosted implementation of the same control plane — your devices still form a WireGuard mesh, but the coordinator runs on a server you control. It is an alternative worth knowing about, not a supported Mushroom Pi setup path, and this guide does not cover installing it.

Self-hosters may also choose a different remote-access approach entirely, or stay LAN-only.
