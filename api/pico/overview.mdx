Each Raspberry Pi Pico 2W running the `mushpi-grow` MicroPython firmware includes a small HTTP server built on [Microdot](https://github.com/miguelgrinberg/microdot). This server listens on port 5000 and provides three endpoints: one for reading the current sensor values and relay states, one for issuing relay commands, and one for unit discovery. The Mushroom Pi backend polls this API every 60 seconds to collect readings and to proxy control commands from the dashboard — but you can also call it directly from any HTTP client on the same network.

## Base URL

```
http://<pico-ip>:5000
```

Replace `<pico-ip>` with the local network IP address of the Pico unit. You can find this in the backend dashboard under the unit's detail view, or in the response from `GET /api/units/:id` (see [Units](/api/units)).

<Note>
  This API is primarily designed for the NestJS backend to consume. Sending commands directly to the Pico bypasses the backend's automatic hysteresis control loop and may cause the relay state to be overridden at the next polling cycle. Use direct calls for diagnostics, hardware testing, or one-off manual overrides — not as a replacement for the backend control flow.
</Note>

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/status` | Returns current sensor readings (temperature, humidity) and the live state of all three relays |
| `POST` | `/control` | Sets a relay to a specified on/off state |
| `GET` | `/announce` | Returns the unit's identity (ID and firmware version) for server discovery |

For full request and response details, see [Pico Endpoints](/api/pico/endpoints).

## No Authentication

The Pico firmware HTTP server does not implement authentication. Access control relies entirely on your network configuration — the Pico should only be reachable from trusted devices on your local LAN. Avoid exposing port 5000 through your router or firewall.
