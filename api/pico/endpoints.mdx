The `mushpi-grow` MicroPython firmware exposes three HTTP endpoints through its Microdot server on port 5000. These endpoints form the entire interface between the Pico 2W and the NestJS backend — the backend reads `/status` on every 60-second poll, sends relay commands to `/control`, and uses `/announce` for initial unit discovery. You can call any of these endpoints directly from a terminal or script for diagnostics and manual control.

---

## GET /status

Returns the current sensor reading from the DHT11 sensor and the live state of all three relay outputs. This is the primary endpoint polled by the backend on its 60-second cron schedule.

### Request

```bash
curl http://<pico-ip>:5000/status
```

### Response `200 OK`

```json
{
  "temperature": 22.5,
  "humidity": 88.0,
  "relays": {
    "humidifier": false,
    "fan": true,
    "heater": false
  },
  "uptime": 3600
}
```

<ResponseField name="temperature" type="number">
  Current ambient temperature in degrees Celsius as measured by the DHT11 sensor.
</ResponseField>

<ResponseField name="humidity" type="number">
  Current relative humidity percentage as measured by the DHT11 sensor.
</ResponseField>

<ResponseField name="relays" type="object">
  The live state of each relay output at the time of the request.

  <Expandable title="relay fields">
    <ResponseField name="relays.humidifier" type="boolean">
      `true` if the humidifier relay is currently energised.
    </ResponseField>

    <ResponseField name="relays.fan" type="boolean">
      `true` if the fan relay is currently energised.
    </ResponseField>

    <ResponseField name="relays.heater" type="boolean">
      `true` if the heater relay is currently energised.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="uptime" type="integer">
  Number of seconds since the Pico firmware last booted.
</ResponseField>

## POST /control

Sets a single relay to the specified on/off state. The command is applied immediately and persists until the Pico's local hysteresis loop next evaluates conditions and issues its own relay update.

### Request Body

<ParamField body="relay" type="string" required>
  The relay to control. One of `"humidifier"`, `"fan"`, or `"heater"`.
</ParamField>

<ParamField body="state" type="boolean" required>
  `true` to energise (switch on) the relay; `false` to de-energise (switch off) the relay.
</ParamField>

### Request

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{"relay": "humidifier", "state": true}' \
  http://<pico-ip>:5000/control
```

### Response `200 OK`

```json
{
  "relay": "humidifier",
  "state": true
}
```

<Warning>
  Calling `/control` directly overrides the Pico's automatic hysteresis control loop for the targeted relay. The loop continues to run locally, so the relay state may be reversed at the next hysteresis evaluation — typically within seconds. Use direct control only for testing, hardware diagnostics, or deliberate temporary overrides. For persistent manual control, use the backend's `POST /api/units/:id/control` endpoint via the dashboard instead.
</Warning>

## GET /announce

Returns the unit's identity information. The backend calls this endpoint during the discovery handshake when a new Pico comes online, and the Pico may also broadcast its presence to the backend at startup.

### Request

```bash
curl http://<pico-ip>:5000/announce
```

### Response `200 OK`

```json
{
  "id": "pico-01",
  "version": "1.0.0"
}
```

<ResponseField name="id" type="string">
  The persistent unique identifier for this Pico unit. This value is set during first-boot provisioning and is used as the primary key throughout the backend API.
</ResponseField>

<ResponseField name="version" type="string">
  The semantic version string of the `mushpi-grow` firmware currently running on this unit.
</ResponseField>
