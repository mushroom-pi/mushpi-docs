Pico units are the physical Raspberry Pi Pico 2W devices deployed in your grow spaces. Each unit reads a DHT11 temperature/humidity sensor and drives humidifier, fan, and heater relays through an onboard hysteresis control loop. The Units API lets you enumerate registered devices, inspect their latest sensor readings and relay states, and send manual relay commands — all over the same REST API that powers the dashboard.

---

## GET /api/units

Returns an array of all Pico units registered with the backend.

### Request

No parameters required.

```bash
curl -H "Authorization: Bearer <your-token>" \
     http://<pi-ip>:3000/api/units
```

### Response `200 OK`

```json
[
  {
    "id": "pico-01",
    "name": "Grow Tent A",
    "ipAddress": "192.168.1.42",
    "lastSeen": "2025-01-15T10:30:00Z",
    "status": "online"
  }
]
```

<ResponseField name="id" type="string">
  Unique identifier for the Pico unit, assigned during first-boot announcement.
</ResponseField>

<ResponseField name="name" type="string">
  Human-readable display name configured for this unit.
</ResponseField>

<ResponseField name="ipAddress" type="string">
  The local network IP address at which the backend last successfully reached the unit.
</ResponseField>

<ResponseField name="lastSeen" type="string (ISO 8601)">
  Timestamp of the most recent successful poll. `null` if the unit has never been polled.
</ResponseField>

<ResponseField name="status" type="string">
  Connectivity status derived from the last poll. One of `"online"` or `"offline"`.
</ResponseField>

## GET /api/units/:id

Returns a single Pico unit by ID, including its latest sensor reading and relay states.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the unit to retrieve (for example, `pico-01`).
</ParamField>

### Request

```bash
curl -H "Authorization: Bearer <your-token>" \
     http://<pi-ip>:3000/api/units/pico-01
```

### Response `200 OK`

```json
{
  "id": "pico-01",
  "name": "Grow Tent A",
  "lastSeen": "2025-01-15T10:30:00Z",
  "latestReading": {
    "temperature": 22.5,
    "humidity": 88.0,
    "timestamp": "2025-01-15T10:30:00Z"
  },
  "relays": {
    "humidifier": false,
    "fan": true,
    "heater": false
  }
}
```

<ResponseField name="id" type="string">
  Unique identifier for the unit.
</ResponseField>

<ResponseField name="name" type="string">
  Human-readable display name.
</ResponseField>

<ResponseField name="lastSeen" type="string (ISO 8601)">
  Timestamp of the most recent successful poll.
</ResponseField>

<ResponseField name="latestReading" type="object">
  The most recent sensor reading stored in the database for this unit.

  <Expandable title="latestReading fields">
    <ResponseField name="latestReading.temperature" type="number">
      Temperature in degrees Celsius as read by the DHT11 sensor.
    </ResponseField>

    <ResponseField name="latestReading.humidity" type="number">
      Relative humidity percentage as read by the DHT11 sensor.
    </ResponseField>

    <ResponseField name="latestReading.timestamp" type="string (ISO 8601)">
      When this reading was recorded.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="relays" type="object">
  Current logical state of each relay as reported in the last poll.

  <Expandable title="relay fields">
    <ResponseField name="relays.humidifier" type="boolean">
      `true` if the humidifier relay is currently active.
    </ResponseField>

    <ResponseField name="relays.fan" type="boolean">
      `true` if the fan relay is currently active.
    </ResponseField>

    <ResponseField name="relays.heater" type="boolean">
      `true` if the heater relay is currently active.
    </ResponseField>
  </Expandable>
</ResponseField>

## POST /api/units/:id/control

Sends a relay control command to the specified Pico unit. The backend proxies the command directly to the unit's firmware API.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the target unit.
</ParamField>

### Request Body

<ParamField body="relay" type="string" required>
  The relay to control. One of `"humidifier"`, `"fan"`, or `"heater"`.
</ParamField>

<ParamField body="state" type="boolean" required>
  `true` to switch the relay on; `false` to switch it off.
</ParamField>

```bash
curl -X POST \
  -H "Authorization: Bearer <your-token>" \
  -H "Content-Type: application/json" \
  -d '{"relay": "humidifier", "state": true}' \
  http://<pi-ip>:3000/api/units/pico-01/control
```

### Response `200 OK`

Returns the updated relay state on success.

```json
{
  "relay": "humidifier",
  "state": true
}
```

<Note>
  Sending a manual command overrides the Pico's automatic hysteresis control loop for that relay until the next control cycle. The backend resumes automatic polling every 60 seconds regardless.
</Note>
