title: "Releases and Versioning"
description: "How Mushroom Pi versions the suite, what a release is, and where the single canonical changelog lives."

Mushroom Pi ships as one versioned suite, and **GitHub Releases is its single canonical changelog**. This page explains what the version numbers mean and where to find the per-release record. It is written once and does not change from release to release — there are no per-release notes, release summaries, or "latest version" pointers hosted on this site.

## One suite-wide version

The whole system — the Pico firmware (`mushpi-grow`), the server (`mushpi-server`), the dashboard (`mushpi-client`), the mock unit (`mushpi-mock`), and the release repo (`mushpi-hub`) — shares **one SemVer version**, `MAJOR.MINOR.PATCH`. When a release is cut, the five move together to the same number; none carries an independent version of its own.

Every version string is a strict `MAJOR.MINOR.PATCH` — no pre-release suffixes (`-rc`) and no build metadata (`+build`).

## `api_version` is not a release number

Separate from the suite version is **`api_version`** — a plain integer marking the generation of the Pico↔Server REST contract. It is bumped only when that contract breaks (an endpoint removed or renamed, an incompatible request or response shape), never for additive changes or bug fixes.

The server reads the `api_version` a unit reports and **judges** it against its supported range, flagging the unit `compatible`, `incompatible`, or `unknown`. It flags an out-of-range value — it never rejects the unit. `api_version` is a contract generation, not a release and not a version of anything.

## What a release is

A release is a **`v*` git tag** in the release repository (`mushpi-hub`) — for example `v0.9.0`. The single canonical per-release record is the **GitHub Release** attached to that tag: what changed, what to test, and any upgrade notes.

## The changelog lives on GitHub

The docs you are reading deliberately do **not** host a changelog. Per-release notes and release summaries all live in the GitHub Releases index, which is always current:

**[https://github.com/mushroom-pi/mushpi-hub/releases](https://github.com/mushroom-pi/mushpi-hub/releases)**

Always link to the **index**, never to a specific tag, so the pointer stays valid whether a release is ahead, deleted, or not yet cut.
