The first time the container starts, the hub prepares itself and then simply waits for you to open the dashboard. There is no setup wizard and no account to create — the dashboard loads the moment it is reachable.

## The first start

When you run `docker compose up -d` for the first time, the container does the preparation for you:

1. It creates the data directory on the host — the path you set as `MUSHPI_DATA_DIR`, defaulting to `./mushpi-data` beside the compose file — along with its `images` and `logs` subdirectories.
2. It corrects the directory's ownership so the server user can write to it. You never create the directory yourself.
3. The server creates its SQLite database at `/data/app.sqlite` inside that directory.

Every later start reuses the same directory, so your data survives restarts and updates. Do not prepare the directory by hand — the container does it on every start.

## Find the hub's address

The dashboard is served on port 3000. To open it, find the hub's local address:

```bash
hostname -I
```

Open `http://<hub-ip>:3000` in any browser on the same network, using the first address that command prints. The dashboard loads directly — there is no login page.

## Configure the timezone

The hub stores one setting that you configure from the dashboard: the timezone, which it uses to render readings and batch timestamps in your local time. Open the dashboard's **Settings** page and set it — see [Settings](/dashboard/settings).

Everything else about how the hub runs is configured in `.env` before the container starts, covered in [Self-hosting](/deployment/self-hosting). There is nothing else to complete on first boot.
